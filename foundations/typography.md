# Typography V1

## 基本方針

日本語本文は、読みやすいサンセリフ体を基本にします。

装飾書体は見出しを含めて原則使用しません。

書体の種類を増やすより、サイズ、太さ、余白で階層を作ります。

書体は雰囲気だけで決めず、その文字が誰の声・どの役割を表すかで選びます。

## 推奨フォント

Webでは次の順序を基本候補とします。

```css
font-family: "Noto Sans JP", "Hiragino Sans", "Yu Gothic", Meiryo, sans-serif;
```

`Noto Sans JP` を日本語の第一候補とします。

利用環境に存在しないフォントを前提にしません。

フォントファイルをリポジトリへ同梱しません。

Web font CDNや外部runtime dependencyの導入は、このFoundationだけでは要求しません。

## 話者と役割で書体を選ぶ

本文、説明、注意書き、CTA、安全情報は、中立的で読みやすいゴシック体を使います。

人の投稿や人の声を明示的に表す短い箇所だけ、手書き系書体を限定使用できます。

AIの返答は、中立的なゴシック体または少し柔らかいゴシック体を基本にします。

AIの返答を手書き化したり、書体だけで強いキャラクターを付与したりすることを既定にしません。

丸ゴシックは、親しみやすさが必要な箇所で選択できます。

ただし、紙面や画面の全体を丸ゴシックへ一律に置き換えることを既定にしません。

## 書体数を増やしすぎない

日本語フォントファミリーは原則2系統までとします。

3系統以上を常態化させません。

基本の目安は、紙面・画面の大半を中立的なゴシック体で構成し、手書き系は人の声を示す小さな範囲だけに使うことです。

`Noto Sans JP 80〜90% / 手書き系 10〜20%` は、限定使用の感覚を共有するためのヒューリスティックです。

この比率を厳密な面積・文字数の合格基準にはしません。

## 手書き系を使わない箇所

次の情報には手書き系書体を使用しません。

- 操作や行動を求める指示。
- 安全情報や注意書き。
- 長文の本文。
- 法人名、制度名、重要な識別情報。
- 可読性の低下が判断や行動へ影響する情報。

## 階層

見出しは本文より明確に大きくし、太さだけに階層を依存させません。

本文は可読性を優先し、狭い行間や長すぎる行長を避けます。

補足情報を極端に小さくして情報量を押し込めません。

## AI・エージェント生成時の組版契約

AIやエージェントへ文字組みを指示するときは、`premium` や `friendly` のような雰囲気語だけに任せず、必要に応じて次を明示します。

- 文字の役割。
- font familyまたはfallback class。
- weight。
- 相対的なサイズと階層。
- tracking / letter spacing。
- leading / line-height。
- alignment。
- 最大行数や折り返し条件。
- 参照画像やフォントサンプルを使う場合の役割。
- 禁止する置換や装飾方向。

これらは生成意図とレビュー基準を定めるものであり、特定書体の完全再現を保証するものではありません。

正確な書体を利用できない場合は、同一書体であると推定せず、利用不可または代替を明示してレビュー対象にします。

### 日本語とLatinのspacingを分ける

強いnegative trackingを全体の既定値にしません。

Latinのdisplay typographyで成立するspacing例を、そのまま日本語の既定値にしません。

日本語では文字の分離と可読性を優先し、行数を合わせるためだけに文字間を圧縮しません。

日本語とLatinが混在する場合は、文字種と役割ごとにtrackingを確認します。

非常に詰めたleadingを全体の既定値にしません。

本文、説明、注意書き、CTA、安全情報では、コンパクトさより可読性を優先します。

日本語とLatinが混在する場合は、文字種、役割、サイズに応じてleadingを確認します。

### 生成用Referenceの境界

フォントサンプル、参考画像、その他の生成入力は、生成用Referenceとして利用できます。

ただし、生成用Referenceは次を意味しません。

```text
generation reference
!= repository font authority
!= runtime dependency
!= license authority
!= accepted output
```

Referenceに近い外観が得られても、それだけで正確な書体identityを証明したことにはなりません。

生成Prompt、provider固有のrecipe、案件固有の要求がこのFoundationの役割・可読性ルールと衝突する場合は、このFoundationを優先します。

## 文体との整合

短い見出しと短い段落を優先します。

強調のための太字、色、大文字表現を重ねすぎません。

## 適用境界

この基準は、新規制作や改訂時の判断基準として使います。

既存のAccepted Reference、in-progress制作物、公開済み成果物へ自動的に遡及適用しません。
