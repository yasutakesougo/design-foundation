# Colors V1

## 基本方針

深い緑を主軸にし、白または低彩度の明るい背景と組み合わせます。

色は意味と階層を補助するために使い、色だけで状態や重要度を伝えません。

配色候補を作る工程と、採用を決める工程を分けます。

外部ツールや参考画像から得た色は候補として扱い、自動的に正本へ追加しません。

## 正本パレット

| Role | Value | Use |
| --- | --- | --- |
| Primary | `#234E3F` | 見出し、主要ボタン、主要な線 |
| Primary Soft | `#DDE9E3` | 面の区切り、淡い強調 |
| Text | `#1F2421` | 本文 |
| Muted Text | `#5F6863` | 補足 |
| Surface | `#FFFFFF` | 基本背景 |
| Surface Soft | `#F5F7F5` | セクション背景 |
| Border | `#D7DDD9` | 境界線 |
| Accent | `#B56F3D` | 限定的な注意・補助強調 |

Accentは面積を小さくし、ブランド主色として使いません。

`success`、`warning`、`error`、`info` などのSemantic Colorは、このFoundationでは固定値を定義しません。

Semantic Colorが必要な案件では、意味、媒体、コントラストを確認したうえで案件側のStyle Guideに定義します。

## 色の役割

色を追加するときは、先に用途を次のいずれかへ割り当てます。

- `background`: ページや紙面全体の背景。
- `surface`: カードや区画などの面。
- `text`: 本文や主要情報。
- `primary`: 主見出し、主要操作、主要な線。
- `accent`: 視線誘導や限定的な補助強調。
- `semantic`: 状態やフィードバックを補助する色。

役割を説明できない色は追加しません。

## 面積比の目安

初稿では、Neutral系を最も広く使い、Primaryを限定し、Accentをさらに小さくします。

開始点の目安は `Neutral 80 / Primary 15 / Accent 5` とします。

この比率は合否基準ではありません。

写真、イラスト、媒体サイズ、情報量によって調整します。

Accentは原則としてPrimaryより広い面積にしません。

写真やイラストの色が強い場合は、UI側のPrimaryとAccentの面積を減らします。

## 配色候補を作る手順

1. 正本パレットと案件固有の既存色を先に固定します。
2. 新しい色が本当に必要かを確認します。
3. 必要な場合だけ、既存色からの派生、参考画像からの抽出、配色ツールなどで候補を作ります。
4. 各候補へ `background / surface / text / primary / accent / semantic` の役割を割り当てます。
5. パレット一覧だけで判断せず、実際の文字、背景、面積、画像と組み合わせて確認します。
6. `accessibility.md` の基準でコントラストと色依存を確認します。
7. Human Reviewで採否を決めます。

候補生成ツールは探索を補助するものであり、採用判断を代替しません。

## 参考画像から色を拾う場合

参考画像から抽出した色は、画像固有の照明、写真補正、圧縮、表示環境の影響を受ける可能性があります。

抽出値をそのまま正本色にしません。

既存Primaryとの関係、文字とのコントラスト、実際の使用面積を確認します。

参考画像の雰囲気を再現する目的でも、不要な色数は増やしません。

## 禁止事項

外部の完成パレットで正本パレット全体を置き換えません。

配色候補生成ツールの結果を無検証で採用しません。

同じ画面や紙面に役割の異なるAccentを複数追加しません。

ブランド色を理由なくSemantic Colorへ流用しません。

色だけで状態、重要度、可否、操作可能性を伝えません。

写真やイラストが強い配色のときに、UI側でも高彩度色を増やしません。

パレット単体の見栄えだけでHuman Visual Acceptanceを通しません。

外部配色サービスの継続提供を制作工程の必須条件にしません。

## AIエージェント向け判定手順

AIエージェントは、最初にこの正本パレットと案件固有のStyle Guideを読みます。

案件側に既存ブランド色がある場合は、Foundationの色で上書きせず、競合を報告します。

追加色が不要なら、正本パレット内だけで構成します。

追加色が必要なら、用途、候補値、既存色との関係、想定面積をセットで提示します。

参考画像から色を抽出した場合は、抽出色であることを明記します。

候補は実画面または実寸に近い構成へ割り当ててから評価します。

デジタル表示では、文字と背景、操作に必要な非テキスト要素のコントラストを `accessibility.md` の基準で確認します。

印刷物では、画面上の数値だけで採否を決めず、Human Reviewと実寸確認を残します。

AIエージェントは候補の生成と検査を担当できますが、Foundationへの昇格とHuman Visual Acceptanceを自動で決定しません。

## 運用ルール

同一画面や一面の中で、役割のない追加色を増やしません。

写真やイラストの色が強い場合は、UI側の色数を減らします。

デジタル表示では、文字と背景、操作に必要な非テキスト要素のコントラストを `accessibility.md` の基準で確認します。
